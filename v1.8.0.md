## 🇬🇧 English

### New Features

#### Know when a new version is out
A few seconds after launch, GlideFTP now checks GitHub for a newer published version. When there is one, a bar appears at the bottom of the window (just above the transfer queue when it is open) with a direct download link to the right file for your install: the .exe on Windows, the AppImage, .deb, .rpm or archive on Linux. With the AUR package it shows the `yay -S glideftp-bin` command instead, with a button to copy it. Another button opens the release page with the notes. "Skip this version" hides the bar until the next version, the ✕ hides it until the next launch. Nothing is downloaded or installed by itself. Settings > Updates has the switch to turn the check off, the current version and a "Check now" button. The eye button next to the "?" shows the bar as a test, with the links of the latest published version.

#### Keyboard shortcuts in the file panels
The local and remote panels now understand the shortcuts of any file explorer: Ctrl+A selects everything, F5 refreshes, Backspace goes to the parent folder and Ctrl+F opens the search. They apply to the panel you last clicked in. The refresh and search buttons show their shortcut when you hover them. Typing in the search field no longer acts on the files either: Delete used to open the delete confirmation for the selected files.

#### A warning before overwriting, whatever the way you transfer
Transferring a file that already exists on the other side now always asks first: Replace, Rename or Cancel. Until now only the transfer button and the right-click "Transfer" did it; drag and drop overwrote without warning. It now works the same in both directions (local to server and server to local), when dropping into a folder of the list or the tree, and with the transfer arrow of the tree view.

### Bug Fixes

#### Opening a folder you can't access did nothing
Double-clicking a folder without access rights, such as a NAS folder blocked for everyone, did nothing, without any message. A red bar now shows "Cannot open folder", with the reason given by the server or by the system (for example "550 Permission denied"), and the panel stays where it was. This error is shown in red rather than orange, which looked like a simple warning; a failed paste or path copy stays orange.

#### Renaming: clicking elsewhere now saves the new name
When renaming a file or folder, the new name was only saved with Enter; clicking elsewhere left the field open. Clicking elsewhere now saves it, like in a file explorer. Escape still cancels.

#### Conflict window: the two rename buttons did the same thing
When a file already existed on the other side, "Rename locally" and "Rename on server" both gave the transferred copy a new name at the destination, whatever their label said. Each button now does what it says. When uploading, "Rename on server" sends the file under a new name and leaves your local file as it is, while "Rename locally, then upload" renames your local file first and then sends it under that name. When downloading, it is the same the other way round: "Rename locally" and "Rename on server, then download". A name that is already taken is refused with a message.

## 🇫🇷 Français

### Nouvelles fonctionnalités

#### Être prévenu quand une nouvelle version sort
Quelques secondes après le lancement, GlideFTP vérifie maintenant sur GitHub si une version plus récente a été publiée. Si c'est le cas, un bandeau apparaît en bas de la fenêtre (juste au-dessus de la file de transfert quand elle est ouverte) avec un lien de téléchargement direct vers le bon fichier pour votre installation : le .exe sous Windows, l'AppImage, le .deb, le .rpm ou l'archive sous Linux. Avec le paquet AUR, il affiche à la place la commande `yay -S glideftp-bin`, avec un bouton pour la copier. Un autre bouton ouvre la page de la version avec ses notes. "Ignorer cette version" masque le bandeau jusqu'à la version suivante, le ✕ le masque jusqu'au prochain lancement. Rien n'est téléchargé ni installé tout seul. Paramètres > Mises à jour contient l'interrupteur pour désactiver la vérification, la version actuelle et un bouton "Vérifier maintenant". Le bouton œil à côté du "?" affiche le bandeau en test, avec les liens de la dernière version publiée.

#### Raccourcis clavier dans les panneaux de fichiers
Les panneaux local et distant comprennent maintenant les raccourcis de n'importe quel explorateur de fichiers : Ctrl+A sélectionne tout, F5 actualise, Retour arrière remonte au dossier parent et Ctrl+F ouvre la recherche. Ils s'appliquent au panneau dans lequel vous avez cliqué en dernier. Les boutons Actualiser et Rechercher affichent leur raccourci au survol. Taper dans le champ de recherche n'agit plus non plus sur les fichiers : la touche Suppr ouvrait la confirmation de suppression des fichiers sélectionnés.

#### Un avertissement avant d'écraser, quelle que soit la façon de transférer
Transférer un fichier qui existe déjà de l'autre côté demande maintenant toujours avant : Remplacer, Renommer ou Annuler. Jusqu'ici, seuls le bouton de transfert et le clic droit "Transférer" le faisaient ; le glisser-déposer écrasait sans prévenir. Cela fonctionne maintenant de la même façon dans les deux sens (du local vers le serveur et du serveur vers le local), en déposant dans un dossier de la liste ou de l'arborescence, et avec la flèche de transfert de la vue arborescente.

### Corrections de bugs

#### Ouvrir un dossier inaccessible ne faisait rien
Double-cliquer sur un dossier sans droits d'accès, comme un dossier du NAS bloqué pour tout le monde, ne faisait rien, sans aucun message. Une barre rouge affiche maintenant "Impossible d'ouvrir le dossier", avec la raison donnée par le serveur ou par le système (par exemple "550 Permission denied"), et le panneau reste là où il était. Cette erreur s'affiche en rouge plutôt qu'en orange, qui ressemblait à un simple avertissement ; un collage ou une copie de chemin qui échoue reste en orange.

#### Renommer : cliquer ailleurs enregistre maintenant le nouveau nom
Quand on renommait un fichier ou un dossier, le nouveau nom n'était enregistré qu'avec Entrée ; cliquer ailleurs laissait le champ ouvert. Cliquer ailleurs l'enregistre maintenant, comme dans un explorateur de fichiers. Échap annule toujours.

#### Fenêtre de conflit : les deux boutons de renommage faisaient la même chose
Quand un fichier existait déjà de l'autre côté, "Renommer localement" et "Renommer sur le serveur" donnaient tous les deux un nouveau nom à la copie transférée, à destination, quel que soit leur libellé. Chaque bouton fait maintenant ce qu'il annonce. Lors d'un envoi, "Renommer sur le serveur" envoie le fichier sous un nouveau nom sans toucher à votre fichier local, et "Renommer localement puis envoyer" renomme d'abord votre fichier local puis l'envoie sous ce nom. Lors d'un téléchargement, c'est l'inverse : "Renommer localement" et "Renommer sur le serveur puis télécharger". Un nom déjà pris est refusé avec un message.
