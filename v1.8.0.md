## 🇬🇧 English

### New Features

#### Know when a new version is out
A few seconds after launch, GlideFTP now checks GitHub for a newer published version. When there is one, a bar appears at the bottom of the window (just above the transfer queue when it is open) with a direct download link to the right file for your install: the .exe on Windows, the AppImage, .deb, .rpm or archive on Linux. With the AUR package it shows the `yay -S glideftp-bin` command instead, with a button to copy it. Another button opens the release page with the notes. "Skip this version" hides the bar until the next version, the ✕ hides it until the next launch. Nothing is downloaded or installed by itself. Settings > Updates has the switch to turn the check off, the current version and a "Check now" button. The eye button next to the "?" shows the bar as a test, with the links of the latest published version.

#### Keyboard shortcuts in the file panels
The local and remote panels now understand the shortcuts of any file explorer: Ctrl+A selects everything, F5 refreshes, Backspace goes to the parent folder, Ctrl+F opens the search and Ctrl+Shift+N creates a new folder (with a folder selected, GlideFTP asks whether to create it here or inside the selected folder, like with the right-click). They apply to the panel you last clicked in. The refresh, search and new folder buttons show their shortcut when you hover them. Typing in the search field no longer acts on the files either: Delete used to open the delete confirmation for the selected files.

#### A warning before overwriting, whatever the way you transfer
Transferring a file that already exists on the other side now always asks first: Replace, Rename or Cancel. Until now only the transfer button and the right-click "Transfer" did it; drag and drop overwrote without warning. It now works the same in both directions (local to server and server to local), when dropping into a folder of the list or the tree, and with the transfer arrow of the tree view.

#### Create a text file straight from the right-click menu
Right-clicking a file, a folder or an empty area of a panel now offers "New text file", on your computer as well as on the server. Type a name (".txt" is added if you don't give an extension), the file is created and opens right away in your usual text editor. For a file on the server, GlideFTP offers to send it back as soon as you save, so there is no need to create it on your computer and upload it anymore. On a folder, you choose whether to create it in that folder or in the current one, as with "New folder".

#### See the size of a folder
Right-click a folder (or several selected folders) and choose "Calculate size", on your computer as well as on the server. The total grows in the Size column while it is computed, then stays there until you change folder or refresh; hovering it shows the number of files. On a server this can take a while for a large folder, since every subfolder has to be listed, so it is only done when you ask. NAS system folders (snapshots, recycle bin) are not counted.

#### Read the release notes inside the app
The notes of each version can now be read without leaving GlideFTP, in French or in English depending on the app's language. Click the version number at the bottom left of the settings, or use the "Release notes" button in Settings > Updates. When a new version is out, the update bar has a "Release notes" button too, to see what it brings before downloading it.

#### Favourite folders and files
Right-click a folder or a file and choose "Add to favourites", or click the star next to the path to add the folder you are in. Favourites show at the top of the panel, above the folder content, and stay there wherever you go: one click opens a folder, or takes you to a file and selects it. The server's favourites are kept for each server, those of your computer are the same for all of them. The block can be folded, and renaming, moving or deleting a favourite in GlideFTP updates it.

Favourites are saved in a `favorites.json` file, next to the sites and settings:
- Linux: `~/.config/GlideFTP/favorites.json`
- Windows: `%APPDATA%\GlideFTP\favorites.json`

#### Resume an interrupted transfer, and keep your transfers when you disconnect or quit
A cut transfer no longer has to start again from zero. In "Failed", "Resume" continues a file where it stopped, to the byte, over FTP and SFTP alike; "Start over" sends it again from the beginning, and "Abandon" removes it along with the incomplete file it left (on your computer, it goes to the trash). If the source file changed in the meantime, the transfer starts again from zero rather than mixing two versions.

When you disconnect, close a tab or quit GlideFTP while transfers are still running, GlideFTP asks what to do with them: cancel and stay connected, stop them, or keep them to resume later. Kept transfers stay in "Pending" as paused, and the next time you connect to the same server a bar offers to resume them all where they stopped. If you answer "Later", it comes back as soon as you resume one of them by hand. A lost connection keeps its transfers the same way. The queue is also saved as it goes, so after a crash or a power cut you find your transfers at the next launch.

When a file already exists at the destination but is smaller than the original, the conflict window also offers "Resume".

The queue is saved in a `queue.json` file, next to the sites and settings:
- Linux: `~/.config/GlideFTP/queue.json`
- Windows: `%APPDATA%\GlideFTP\queue.json`

#### Synchronized browsing
Turn it on with the link button at the top of the panels, or Ctrl+Y. When you open a folder in one panel, the other panel opens the folder of the same name, and ".." goes up on both sides: handy to keep a local copy of a site in step with the server. If the folder is missing on the other side, GlideFTP asks whether to create it and open it, to create it without asking again from now on, or to turn synchronized browsing off. Typing a path, opening a favourite or a search result turns it off, since there is no clear match on the other side. Settings > Synchronized browsing explains it and has the "create the missing folder without asking" option.

#### Compare the two panels
Turn it on with the two-columns button at the top of the panels, or Ctrl+O. Rows are coloured: yellow, the file or folder is only on one side; green, the file is newer than the one on the other side; red, the two files are not the same size. Hover a coloured row to see why, for example "Different size: 4.0 GB here, 3.6 GB on the server". A legend shows under the panels while the comparison is on. Settings > Panel comparison lets you compare by size (default) or by date, hide identical files, and align the rows of both panels: the same names on the same lines, with an empty line where a file only exists on the other side, and both lists scroll together.

#### Case-sensitive name sorting
A new option in Settings > Interface sorts names character by character: names starting with a dot, then those in upper case, then those in lower case. It is off by default, so names keep the usual alphabetical order, with upper and lower case mixed. Folders stay above files either way.

#### Settings are saved as you change them
No more "Save" button: each change in Settings is applied and saved at once, and "Settings saved" confirms it. A text or number field is saved when you leave it, so a path or a number is never saved half typed. Switching to the light theme now asks for confirmation first, just in case your eyes were not ready.

#### Send only the differences
While the panels are compared, right-click an empty area, a folder or a file to find "Send differences" on the local side, or "Download differences" on the server side. A window lists every coloured file and folder of that panel, all checked: uncheck the ones you want to keep, the button shows the total size as you go. Files that already exist on the other side go through the usual overwrite warning, which also offers to resume a copy cut short. Folders that only exist on one side are sent with all their content. With no difference in the folder, the entry is greyed out with "(none)".

#### Choose what happens when the transfer queue is finished
Right-click the transfer queue to choose, for the current queue: show a notification bubble, play a sound, then do nothing, quit GlideFTP, shut the computer down or run a command of your own. The bubble shows at the bottom right of GlideFTP, framed with your accent colour, with how many transfers succeeded or failed. It can be turned on for every queue in Settings > Notifications; the bubble and sound ticked in the menu only apply to the current queue. A badge in the queue header reminds you of the chosen action and cancels it in one click. Before shutting down or quitting, a countdown shows in the middle of the window (60 seconds for the shutdown, 10 for quitting) with a button to cancel. The command receives the number of successful and failed transfers in GLIDEFTP_DONE and GLIDEFTP_FAILED.

### Bug Fixes

#### Opening a folder you can't access did nothing
Double-clicking a folder without access rights, such as a NAS folder blocked for everyone, did nothing, without any message. A red bar now shows "Cannot open folder", with the reason given by the server or by the system (for example "550 Permission denied"), and the panel stays where it was. This error is shown in red rather than orange, which looked like a simple warning; a failed paste or path copy stays orange.

#### Renaming: clicking elsewhere now saves the new name
When renaming a file or folder, the new name was only saved with Enter; clicking elsewhere left the field open. Clicking elsewhere now saves it, like in a file explorer. Escape still cancels.

#### Conflict window: the two rename buttons did the same thing
When a file already existed on the other side, "Rename locally" and "Rename on server" both gave the transferred copy a new name at the destination, whatever their label said. Each button now does what it says. When uploading, "Rename on server" sends the file under a new name and leaves your local file as it is, while "Rename locally, then upload" renames your local file first and then sends it under that name. When downloading, it is the same the other way round: "Rename locally" and "Rename on server, then download". A name that is already taken is refused with a message.

#### With several tabs open, waiting transfers could go to the wrong server
A transfer waiting in the queue started on the tab that was active when its turn came, not on the server it was added for. If you sent files to one server and then switched to another tab, the files still waiting were sent to that other server, or failed there; downloads could even take a file of the same name from the wrong server and overwrite yours. Each transfer now stays on the server it was added for, whatever tab you open or connect in the meantime. If that connection is closed, its transfers stop with the message "Connection to server closed" instead of moving to another one.

#### The ✕ of a connection tab said "Close"
With several servers open, hovering the ✕ of a tab showed "Fermer" (in French even with the app in English), although it disconnects from that server. It now says "Disconnect".

#### Linux: "FTP" cut off in the Protocol menu of the connection screen
On some Linux setups, the text of the Protocol menu (FTP / SFTP) on the connection screen was shifted down and cut off, because the menu was drawn by the system theme. GlideFTP now draws it itself, so it looks the same on every system and theme.

#### Synchronized browsing: words cut in the "missing folder" window
When a folder was missing on the other side, the title of the window could cut a word in two when going to the next line, depending on the length of the folder path. Words now always go to the next line whole; only a path too long to fit on one line is split.

## 🇫🇷 Français

### Nouvelles fonctionnalités

#### Être prévenu quand une nouvelle version sort
Quelques secondes après le lancement, GlideFTP vérifie maintenant sur GitHub si une version plus récente a été publiée. Si c'est le cas, un bandeau apparaît en bas de la fenêtre (juste au-dessus de la file de transfert quand elle est ouverte) avec un lien de téléchargement direct vers le bon fichier pour votre installation : le .exe sous Windows, l'AppImage, le .deb, le .rpm ou l'archive sous Linux. Avec le paquet AUR, il affiche à la place la commande `yay -S glideftp-bin`, avec un bouton pour la copier. Un autre bouton ouvre la page de la version avec ses notes. "Ignorer cette version" masque le bandeau jusqu'à la version suivante, le ✕ le masque jusqu'au prochain lancement. Rien n'est téléchargé ni installé tout seul. Paramètres > Mises à jour contient l'interrupteur pour désactiver la vérification, la version actuelle et un bouton "Vérifier maintenant". Le bouton œil à côté du "?" affiche le bandeau en test, avec les liens de la dernière version publiée.

#### Raccourcis clavier dans les panneaux de fichiers
Les panneaux local et distant comprennent maintenant les raccourcis de n'importe quel explorateur de fichiers : Ctrl+A sélectionne tout, F5 actualise, Retour arrière remonte au dossier parent, Ctrl+F ouvre la recherche et Ctrl+Maj+N crée un nouveau dossier (avec un dossier sélectionné, GlideFTP demande s'il faut le créer ici ou dans le dossier sélectionné, comme avec le clic droit). Ils s'appliquent au panneau dans lequel vous avez cliqué en dernier. Les boutons Actualiser, Rechercher et Nouveau dossier affichent leur raccourci au survol. Taper dans le champ de recherche n'agit plus non plus sur les fichiers : la touche Suppr ouvrait la confirmation de suppression des fichiers sélectionnés.

#### Un avertissement avant d'écraser, quelle que soit la façon de transférer
Transférer un fichier qui existe déjà de l'autre côté demande maintenant toujours avant : Remplacer, Renommer ou Annuler. Jusqu'ici, seuls le bouton de transfert et le clic droit "Transférer" le faisaient ; le glisser-déposer écrasait sans prévenir. Cela fonctionne maintenant de la même façon dans les deux sens (du local vers le serveur et du serveur vers le local), en déposant dans un dossier de la liste ou de l'arborescence, et avec la flèche de transfert de la vue arborescente.

#### Créer un fichier texte directement depuis le clic droit
Un clic droit sur un fichier, un dossier ou une zone vide d'un panneau propose maintenant "Nouveau fichier texte", sur votre ordinateur comme sur le serveur. Tapez un nom (".txt" est ajouté si vous ne donnez pas d'extension), le fichier est créé et s'ouvre aussitôt dans votre éditeur de texte habituel. Pour un fichier sur le serveur, GlideFTP propose de le renvoyer dès que vous enregistrez : plus besoin de le créer sur votre ordinateur puis de l'envoyer. Sur un dossier, vous choisissez de le créer dans ce dossier ou dans le dossier actuel, comme pour "Nouveau dossier".

#### Voir la taille d'un dossier
Faites un clic droit sur un dossier (ou plusieurs dossiers sélectionnés) et choisissez "Calculer la taille", sur votre ordinateur comme sur le serveur. Le total augmente dans la colonne Taille pendant le calcul, puis y reste jusqu'à ce que vous changiez de dossier ou actualisiez ; le survol affiche le nombre de fichiers. Sur un serveur, le calcul peut prendre un moment pour un gros dossier, car chaque sous-dossier doit être listé : il n'est donc fait que quand vous le demandez. Les dossiers système du NAS (instantanés, corbeille) ne sont pas comptés.

#### Lire les notes de version dans l'appli
Les notes de chaque version se lisent maintenant sans quitter GlideFTP, en français ou en anglais selon la langue de l'appli. Cliquez sur le numéro de version en bas à gauche des paramètres, ou utilisez le bouton "Notes de version" dans Paramètres > Mises à jour. Quand une nouvelle version sort, le bandeau de mise à jour a lui aussi un bouton "Notes de version", pour voir ce qu'elle apporte avant de la télécharger.

#### Dossiers et fichiers favoris
Faites un clic droit sur un dossier ou un fichier et choisissez "Ajouter aux favoris", ou cliquez sur l'étoile à côté du chemin pour ajouter le dossier où vous êtes. Les favoris s'affichent en haut du panneau, au-dessus du contenu du dossier, et y restent où que vous alliez : un clic ouvre un dossier, ou vous amène à un fichier en le sélectionnant. Les favoris du serveur sont gardés pour chaque serveur, ceux de votre ordinateur sont les mêmes pour tous. Le bloc peut être replié, et renommer, déplacer ou supprimer un favori dans GlideFTP le met à jour.

Les favoris sont enregistrés dans un fichier `favorites.json`, à côté des sites et des paramètres :
- Linux : `~/.config/GlideFTP/favorites.json`
- Windows : `%APPDATA%\GlideFTP\favorites.json`

#### Reprendre un transfert interrompu, et garder ses transferts en se déconnectant ou en quittant
Un transfert coupé n'a plus besoin de repartir de zéro. Dans « Échoués », « Reprendre » continue le fichier là où il s'est arrêté, à l'octet près, en FTP comme en SFTP ; « Recommencer » le renvoie depuis le début, et « Abandonner » le retire avec le fichier incomplet qu'il a laissé (sur votre ordinateur, il part à la corbeille). Si le fichier d'origine a changé entre-temps, le transfert repart de zéro plutôt que de mélanger deux versions.

Quand vous vous déconnectez, fermez un onglet ou quittez GlideFTP alors que des transferts tournent encore, GlideFTP demande quoi en faire : annuler et rester connecté, les arrêter, ou les garder pour les reprendre plus tard. Les transferts gardés restent dans « En attente », en pause, et à votre prochaine connexion au même serveur un bandeau propose de tous les reprendre là où ils se sont arrêtés. Si vous répondez « Plus tard », il revient dès que vous en reprenez un à la main. Une connexion perdue garde ses transferts de la même façon. La file est aussi enregistrée au fur et à mesure : après un plantage ou une coupure de courant, vous retrouvez vos transferts au lancement suivant.

Quand un fichier existe déjà à destination mais est plus petit que l'original, la fenêtre de conflit propose aussi « Reprendre ».

La file est enregistrée dans un fichier `queue.json`, à côté des sites et des paramètres :
- Linux : `~/.config/GlideFTP/queue.json`
- Windows : `%APPDATA%\GlideFTP\queue.json`

#### Navigation synchronisée
Activez-la avec le bouton en forme de lien en haut des panneaux, ou Ctrl+Y. Quand vous ouvrez un dossier dans un panneau, l'autre panneau ouvre le dossier du même nom, et ".." remonte des deux côtés : pratique pour garder une copie locale d'un site au même endroit que le serveur. Si le dossier manque de l'autre côté, GlideFTP demande s'il faut le créer et l'ouvrir, le créer sans plus demander à l'avenir, ou désactiver la navigation synchronisée. Taper un chemin, ouvrir un favori ou un résultat de recherche la désactive, faute d'équivalent clair de l'autre côté. Paramètres > Navigation synchronisée l'explique et propose l'option "créer le dossier manquant sans demander".

#### Comparer les deux panneaux
Activez-la avec le bouton à deux colonnes en haut des panneaux, ou Ctrl+O. Les lignes sont colorées : jaune, le fichier ou le dossier n'existe que d'un côté ; vert, le fichier est plus récent que celui d'en face ; rouge, les deux fichiers n'ont pas la même taille. Survolez une ligne colorée pour en voir la raison, par exemple "Taille différente : 4,0 Go ici, 3,6 Go sur le serveur". Une légende s'affiche sous les panneaux tant que la comparaison est active. Paramètres > Comparaison des panneaux permet de comparer par taille (par défaut) ou par date, de masquer les fichiers identiques, et d'aligner les lignes des deux panneaux : les mêmes noms sur les mêmes lignes, avec une ligne vide là où un fichier n'existe que de l'autre côté, et les deux listes défilent ensemble.

#### Trier les noms en respectant la casse
Une nouvelle option dans Paramètres > Interface trie les noms caractère par caractère : ceux qui commencent par un point, puis ceux en majuscule, puis ceux en minuscule. Elle est désactivée par défaut : les noms gardent l'ordre alphabétique habituel, majuscules et minuscules mélangées. Les dossiers restent au-dessus des fichiers dans les deux cas.

#### Les paramètres s'enregistrent dès qu'on les change
Plus de bouton "Enregistrer" : chaque changement dans les Paramètres est appliqué et enregistré tout de suite, et "Paramètres enregistrés" le confirme. Un champ de texte ou de nombre est enregistré quand vous le quittez, pour ne jamais enregistrer un chemin ou un nombre à moitié tapé. Passer au thème clair demande maintenant une confirmation, au cas où vos yeux ne seraient pas prêts.

#### Envoyer seulement les différences
Pendant la comparaison des panneaux, faites un clic droit sur un espace vide, un dossier ou un fichier pour trouver "Envoyer les différences" côté local, ou "Télécharger les différences" côté serveur. Une fenêtre liste tous les fichiers et dossiers colorés du panneau, tous cochés : décochez ceux à laisser de côté, le bouton affiche la taille totale au fur et à mesure. Les fichiers qui existent déjà de l'autre côté passent par l'avertissement habituel avant d'écraser, qui propose aussi de reprendre une copie interrompue. Les dossiers présents d'un seul côté sont envoyés avec tout leur contenu. Sans aucune différence dans le dossier, l'entrée est grisée avec "(aucune)".

#### Choisir ce qui se passe quand la file d'attente est terminée
Un clic droit sur la file d'attente permet de choisir, pour la file en cours : afficher une bulle de notification, jouer un son, puis ne rien faire, quitter GlideFTP, éteindre l'ordinateur ou exécuter votre propre commande. La bulle s'affiche en bas à droite de GlideFTP, encadrée de votre couleur d'accent, avec le nombre de transferts réussis ou échoués. Elle peut être activée pour toutes les files dans Paramètres > Notifications ; la bulle et le son cochés dans le menu ne valent que pour la file en cours. Un badge dans l'en-tête de la file rappelle l'action choisie et l'annule d'un clic. Avant d'éteindre ou de quitter, un compte à rebours s'affiche au milieu de la fenêtre (60 secondes pour l'extinction, 10 pour quitter) avec un bouton pour annuler. La commande reçoit le nombre de transferts réussis et échoués dans GLIDEFTP_DONE et GLIDEFTP_FAILED.

### Corrections de bugs

#### Ouvrir un dossier inaccessible ne faisait rien
Double-cliquer sur un dossier sans droits d'accès, comme un dossier du NAS bloqué pour tout le monde, ne faisait rien, sans aucun message. Une barre rouge affiche maintenant "Impossible d'ouvrir le dossier", avec la raison donnée par le serveur ou par le système (par exemple "550 Permission denied"), et le panneau reste là où il était. Cette erreur s'affiche en rouge plutôt qu'en orange, qui ressemblait à un simple avertissement ; un collage ou une copie de chemin qui échoue reste en orange.

#### Renommer : cliquer ailleurs enregistre maintenant le nouveau nom
Quand on renommait un fichier ou un dossier, le nouveau nom n'était enregistré qu'avec Entrée ; cliquer ailleurs laissait le champ ouvert. Cliquer ailleurs l'enregistre maintenant, comme dans un explorateur de fichiers. Échap annule toujours.

#### Fenêtre de conflit : les deux boutons de renommage faisaient la même chose
Quand un fichier existait déjà de l'autre côté, "Renommer localement" et "Renommer sur le serveur" donnaient tous les deux un nouveau nom à la copie transférée, à destination, quel que soit leur libellé. Chaque bouton fait maintenant ce qu'il annonce. Lors d'un envoi, "Renommer sur le serveur" envoie le fichier sous un nouveau nom sans toucher à votre fichier local, et "Renommer localement puis envoyer" renomme d'abord votre fichier local puis l'envoie sous ce nom. Lors d'un téléchargement, c'est l'inverse : "Renommer localement" et "Renommer sur le serveur puis télécharger". Un nom déjà pris est refusé avec un message.

#### Avec plusieurs onglets, les transferts en attente pouvaient partir vers le mauvais serveur
Un transfert en attente démarrait sur l'onglet actif au moment de son tour, pas sur le serveur pour lequel il avait été ajouté. Si vous envoyiez des fichiers vers un serveur puis passiez sur un autre onglet, les fichiers encore en attente partaient vers cet autre serveur, ou y échouaient ; un téléchargement pouvait même prendre le fichier de même nom sur le mauvais serveur et écraser le vôtre. Chaque transfert reste maintenant sur le serveur pour lequel il a été ajouté, quel que soit l'onglet ouvert ou la connexion lancée entre-temps. Si cette connexion est fermée, ses transferts s'arrêtent avec le message "Connexion à serveur fermée" au lieu de passer sur une autre.

#### La croix d'un onglet de connexion indiquait « Fermer »
Avec plusieurs serveurs ouverts, survoler la croix d'un onglet affichait « Fermer » (en français même avec l'appli en anglais), alors qu'elle déconnecte de ce serveur. Elle indique maintenant « Se déconnecter ».

#### Linux : « FTP » coupé dans le menu Protocole de l'écran de connexion
Sur certaines installations Linux, le texte du menu Protocole (FTP / SFTP) de l'écran de connexion était décalé vers le bas et coupé, car le menu était dessiné par le thème du système. GlideFTP le dessine maintenant lui-même : il a le même aspect sur tous les systèmes et tous les thèmes.

#### Navigation synchronisée : mots coupés dans la fenêtre « dossier manquant »
Quand un dossier manquait de l'autre côté, le titre de la fenêtre pouvait couper un mot en deux en passant à la ligne, selon la longueur du chemin du dossier. Les mots passent maintenant toujours entiers à la ligne suivante ; seul un chemin trop long pour tenir sur une ligne est coupé.
