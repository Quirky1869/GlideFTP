# GlideFTP v1.7.4

---

## 🇬🇧 English

### New Features

#### Tree view for file panels
Each panel now has a toggle button (to the left of the refresh button) that switches between the classic flat list and a hierarchical tree view. The tree loads lazily - folders expand on click, files are visible with their size and can be transferred with a double-click or the arrow button that appears on hover. The tree auto-expands to the current path when entering tree mode. Each panel remembers its own view independently.

#### Intra-panel copy, cut and paste
You can now copy or move files and folders within the same panel - without going through the transfer queue.

- **Ctrl+C** to copy, **Ctrl+X** to cut, **Ctrl+V** to paste into the current directory
- Right-click on any file or folder for Cut / Copy / Paste in the context menu
- Paste into a specific subfolder by right-clicking it and choosing **Paste here**
- Pasting in the same directory automatically generates a unique name: `file (copy).txt`, `file (copy 1).txt`, etc.
- Works in both list view and tree view
- Local copy is instant (OS-level); remote copy is transparent (download + re-upload on the same server)
- A green confirmation banner appears when the operation completes, orange if it fails
- The panel refreshes automatically during and after the operation

#### Intra-panel drag and drop onto folders
Drag files or folders and drop them directly onto a subfolder or the `..` row within the same panel to move them there instantly. Cross-panel drops now also support targeting a specific subfolder - not just the current directory.

#### Connection keepalive
GlideFTP now sends a NOOP/ping to the server every 60 seconds to keep idle connections alive. If the server drops the connection unexpectedly, a dismissible notification banner appears and the panel updates automatically - no more silent freezes requiring a manual reconnect.

#### System trash on local delete
Deleting a local file or folder now sends it to the **OS trash** instead of permanently erasing it:
- **Linux**: follows the XDG Trash specification (`~/.local/share/Trash/`)
- **Windows**: sends to the Recycle Bin via the Windows Shell API

Remote files (FTP/SFTP) are still deleted permanently on the server - there is no server-side trash in either protocol.

#### Accent shadow on the connection card
A new toggle in **Settings > Interface** adds a layered neon glow shadow to the connection card on the main screen, using the active accent color. Off by default.

---

### Bug Fixes

#### Folder transfer was failing with "Not a regular file"
Attempting to transfer a folder (upload or download) resulted in an immediate error. FTP and SFTP both require individual file commands - GlideFTP now walks the folder tree recursively and queues one transfer job per file, with destination subdirectories created automatically.

#### Concurrent transfers had no effect
The **Max simultaneous transfers** setting was saved correctly but never applied to the running queue - transfers always happened one at a time regardless of the value. Additionally, FTP transfers were serialised internally by a connection-level lock even when multiple slots were available. Both issues are fixed: the setting now takes effect immediately when saved, and each FTP transfer opens its own dedicated connection so they can run truly in parallel.

#### "Clear" button in the Failed tab did nothing
The Failed tab groups both `failed` and `cancelled` jobs, but the Clear button only removed `failed` ones, leaving cancelled transfers stuck in the list. Both statuses are now cleared together.

## 🇫🇷 Français

### Nouvelles fonctionnalités

#### Vue arborescente des panneaux de fichiers
Chaque panneau dispose désormais d'un bouton de bascule (à gauche du bouton d'actualisation) pour passer de la liste plate classique à une vue arborescente hiérarchique. L'arbre se charge de façon paresseuse - les dossiers s'ouvrent au clic, les fichiers sont visibles avec leur taille et peuvent être transférés d'un double-clic ou via le bouton fléché qui apparaît au survol. L'arbre se déploie automatiquement jusqu'au répertoire courant à l'entrée dans ce mode. Chaque panneau conserve sa propre vue indépendamment de l'autre.

#### Copier, couper et coller dans le même panneau
Il est maintenant possible de copier ou déplacer des fichiers et dossiers au sein du même panneau, sans passer par la file de transfert.

- **Ctrl+C** pour copier, **Ctrl+X** pour couper, **Ctrl+V** pour coller dans le répertoire courant
- Clic droit sur un fichier ou dossier pour accéder à Couper / Copier / Coller ici dans le menu contextuel
- Coller dans un sous-dossier spécifique en faisant un clic droit dessus puis **Coller ici**
- Coller dans le même répertoire génère automatiquement un nom unique : `fichier (copie).txt`, `fichier (copie 1).txt`, etc.
- Fonctionne en vue liste et en vue arborescente
- La copie locale est instantanée (opération OS) ; la copie distante est transparente (téléchargement puis ré-envoi sur le même serveur)
- Une bannière verte confirme la réussite de l'opération, orange en cas d'erreur
- Le panneau s'actualise automatiquement pendant et après l'opération

#### Drag and drop intra-panneau vers les dossiers
Glissez des fichiers ou dossiers et déposez-les directement sur un sous-dossier ou sur la ligne `..` du même panneau pour les déplacer instantanément. Les dépôts entre panneaux supportent également désormais un dossier cible précis - pas uniquement le répertoire courant.

#### Keepalive de connexion
GlideFTP envoie désormais un NOOP/ping au serveur toutes les 60 secondes pour maintenir les connexions inactives en vie. Si le serveur coupe la connexion de façon inattendue, une bannière de notification apparaît et le panneau se met à jour automatiquement - plus de gel silencieux nécessitant une reconnexion manuelle.

#### Corbeille système lors de la suppression locale
La suppression d'un fichier ou dossier local l'envoie maintenant dans la **corbeille de l'OS** plutôt que de l'effacer définitivement :
- **Linux** : suit la spécification XDG Trash (`~/.local/share/Trash/`)
- **Windows** : envoie dans la Corbeille via l'API Shell Windows

Les fichiers distants (FTP/SFTP) sont toujours supprimés définitivement sur le serveur - aucun des deux protocoles ne dispose de corbeille côté serveur.

#### Ombre d'accentuation sur le panneau de connexion
Un nouveau bouton dans **Paramètres > Interface** ajoute une ombre lumineuse en couches sur le panneau de connexion de l'écran principal, en utilisant la couleur d'accentuation active. Désactivé par défaut.

### Corrections de bugs

#### Le transfert d'un dossier échouait avec "Not a regular file"
Tenter de transférer un dossier (upload ou download) provoquait une erreur immédiate. FTP et SFTP nécessitent des commandes individuelles par fichier - GlideFTP parcourt maintenant l'arborescence de façon récursive et met en file un job de transfert par fichier, avec création automatique des sous-dossiers de destination.

#### Les transferts simultanés n'avaient aucun effet
Le paramètre **Transferts simultanés maximum** était bien sauvegardé mais n'était jamais appliqué à la file en cours d'exécution - les transferts s'effectuaient toujours un par un quel que soit le réglage. De plus, les transferts FTP étaient sérialisés en interne par un verrou sur la connexion, même quand plusieurs slots étaient disponibles. Les deux problèmes sont corrigés : le paramètre prend désormais effet immédiatement à la sauvegarde, et chaque transfert FTP ouvre sa propre connexion dédiée pour s'exécuter véritablement en parallèle.

#### Le bouton "Vider" de l'onglet Échoués ne fonctionnait pas
L'onglet Échoués regroupe les jobs `failed` et `cancelled`, mais le bouton Vider ne supprimait que les `failed`, laissant les transferts annulés bloqués dans la liste. Les deux statuts sont maintenant effacés ensemble.
